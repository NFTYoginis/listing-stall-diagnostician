# Runs

Recorded runs. Not descriptions of runs.

Each folder holds four files, and the order they were committed in is the point:

| File | What it is |
|---|---|
| `expected.md` | The answer key. **Committed before the transcript existed**, in its own commit. `git log --follow` on any pair shows it. |
| `transcript.md` | Verbatim. Every turn, both sides, nothing edited, trimmed, retried, or selected from more than one attempt. Model, effort, timestamps and token usage in the metadata block. |
| `findings.md` | The scoring, assertion by assertion, including where a run disagreed with its key and won. |
| `verify-output.txt` | What `checks/verify.py` said about it, warnings included. |
| `SHA256SUMS` | The `product/` files that produced it. `cd product && shasum -a 256 -c ../runs/NNN-*/SHA256SUMS`. |

The order matters because a key written after a run agrees with that run by construction. A
prediction on record before the fact is the only version of this that means anything.

every gate has a negative fixture and lists by name the requirements no gate covers.

## How cold these are, exactly

Fresh API session per run. The system prompt was `product/` and nothing else — no answer key,
no `tests/`, no `runs/`, no prior conversation. Run 004 carries two turns because it is a
follow-up; every other run is single-shot.

**The scoring is still the builder's.** A run that disagreed with its key was adjudicated by
the same session that wrote the key. That is weaker than an independent scorer and it is why
the cold gate for this build is explicitly not run by its author. RUNS-1 in `OPEN-DEFECTS.md`.

[`PRIOR-RUNS.md`](PRIOR-RUNS.md) is the record of three earlier blind runs that left no
artifacts. It is history, not evidence.
